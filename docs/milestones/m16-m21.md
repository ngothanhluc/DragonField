## Balance passes (post-M21)

### #108 — Signature Active nerf + one hitstop beat per cast (2026-11-28)

The Signature Active (`E`) was too strong and too frequent: every projectile hit and kill shaved its
cooldown (≈4 s effective cooldown in dense rooms), and every projectile of a volley requested a
crit-length hitstop, so a cast stuttered. Now:

- **Damage −20%**, all 4 classes: ninja `1.5 → 1.2`, archer `2.1 → 1.68`, mage `1.35 → 1.08`
  (`novaDamageMultiplier 3.2 → 2.56`), cultivator `1.35 → 1.08`.
- **Cooldown ×1.5** with no recharge from hits or kills:
  ninja `15 000`, archer `14 250`, mage `15 750` (passive `activeCooldownMult 0.8` kept),
  cultivator `16 500`; `hitCooldownReductionMs` / `killCooldownReductionMs` are `0` for all 4 and the
  top-level `activeSkill` block is synced (`cooldownMs 15 000`, `0`/`0`, `barrageDamageMultiplier 1.2`).
- **One hitstop beat per cast** (`core/combat/hit-hitstop.ts`): the first projectile of a Signature
  cast that lands freezes the game `70 ms` (`110 ms` only on a real crit), every later one `0`; the
  crit test compares a bullet with **its own** base damage, so Signature blades no longer read as
  crits. Auto-fire shots keep one beat per hit. Both sims mirror the rule (`PlayerHitHitstop`).
- **Unchanged:** Shadow Conduit, Tempest Barrage, the mage cooldown modifier, projectile
  counts/speed/pierce/TTL, `combat.enemyHitstopMs` (70) and `feel.vfx.critHitstopMs` (110).

`bun run sim:table` after the change (before → after): **55/72** rows win 9/9 (was 72/72) —
ninja 19/24, archer 12/16, mage 8/16, cultivator 16/16; **18.7** Signature casts/run (was 71.5);
every winning row sits in the 12–16 level-up band (range 0–16: a lost run ends early); 52/72 rows
with Evolutions (81). The casts/run drop (no hit/kill recharge) drives the win-rate movement.

The owner accepted that lower win rate and replaced the old "every one of the 72 rows wins 9/9"
contract with the measured ×1.5 table as a **floor**: `BALANCE_FLOOR` in
`tests/helpers/sim-table.ts` (total ≥ 55/72 and per class the numbers above, each tied to its row
count so the floor only applies to the exact `sim:table` matrix). The pure `simTableGateFailures`
is the single gate behind both the `bun run sim:table` exit code and the balance tests; every rule
that does not depend on winning (stand-still loss, dash coverage, one Signature per row, no
cross-class leak, …) stays as strict as before.
